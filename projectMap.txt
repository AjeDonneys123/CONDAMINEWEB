📘 DOCUMENTATION TECHNIQUE : LA LISEUSE (VIEWER)
Cette documentation explique le fonctionnement du composant de visualisation de documents (HomeworkWorkspace.jsx zone haute).
1. Le Concept "Centrage Absolu + Delta"
Contrairement à une image statique, cette image doit pouvoir être zoomée et déplacée.
CSS : Positionne le point d'ancrage de l'image au centre exact du conteneur.
JS : Calcule le décalage (x, y) par rapport à ce centre.
2. Les Règles CSS CRITIQUES (Homework.css)
Ne JAMAIS supprimer ces propriétés sur .main-doc-img ou .viewer-top-area :
code
CSS
.viewer-top-area {
    overflow: hidden;       /* Empêche l'image de dépasser du cadre quand on zoom */
    position: relative;     /* Sert de repère (0,0) pour l'image absolue */
}

.main-doc-img {
    position: absolute;     /* Sort du flux normal pour bouger librement */
    top: 50%;               /* Place le coin haut-gauche au milieu du conteneur */
    left: 50%;              /* Place le coin haut-gauche au milieu du conteneur */
    transform-origin: center center; /* Le zoom se fait depuis le milieu de l'image */
    
    /* INDISPENSABLE POUR LE DRAG & DROP : */
    user-select: none;          /* Empêche de sélectionner l'image comme du texte */
    -webkit-user-drag: none;    /* Empêche le navigateur de créer un "fantôme" de l'image */
    max-width: none;            /* Permet à l'image de dépasser 100% lors du zoom */
}
3. La Formule Mathématique JS (HomeworkWorkspace.jsx)
Le mouvement fluide repose sur une formule de transformation CSS spécifique appliquée via Javascript.
La Formule : translate(-50%, -50%) translate(Xpx, Ypx) scale(S)
translate(-50%, -50%) : C'est la compensation statique. Comme le CSS met le coin haut-gauche à 50%, cette commande recule l'image de la moitié de sa propre taille pour que son centre soit sur le 50% du conteneur.
translate(Xpx, Ypx) : C'est le mouvement ajouté par l'utilisateur (Pan).
scale(S) : C'est le niveau de zoom.
Code JS correspondant :
code
JavaScript
const updateTransform = (refData, refEl) => {
    if(refEl.current) {
        refEl.current.style.transform = `
            translate(-50%, -50%) 
            translate(${refData.current.x}px, ${refData.current.y}px) 
            scale(${refData.current.scale})
        `;
    }
};
4. La Logique de Drag & Drop (Souris)
On n'utilise pas l'API HTML5 Drag&Drop (qui est faite pour déplacer des fichiers), mais des écouteurs de souris basiques pour une fluidité maximale (60fps).
onMouseDown :
On active le mode "drag".
On enregistre la position de la souris au départ (startX).
Important : On attache les écouteurs mousemove et mouseup sur window (pas sur l'image), pour que si la souris sort du cadre, le mouvement continue.
onMouseMove :
On calcule la distance parcourue : NouvelleSouris - AncienneSouris.
On met à jour refData.current.x et y.
On appelle updateTransform directement (sans passer par useState de React pour éviter de re-rendre tout le composant à chaque pixel, ce qui serait lent).
onMouseUp :
On nettoie les écouteurs pour libérer la mémoire.
⚠️ ZONE DE DANGER : NE PAS TOUCHER
Ne pas enlever transform: translate(-50%, -50%) dans le JS, sinon l'image sautera en bas à droite dès qu'on clique.
Ne pas utiliser useState pour stocker x et y pendant le mouvement (trop lent). Garder useRef.
Ne pas enlever -webkit-user-drag: none dans le CSS, sinon on "tire" une copie fantôme de l'image au lieu de déplacer l'image elle-même.

⚡ DOCUMENTATION : LE SYSTÈME APPLY & SNIPPETS
1. Le Concept : "Le Pont Magique"
Le développement classique oblige à créer des fichiers manuellement, copier le code, sauvegarder, recommencer pour le fichier suivant... C'est lent et sujet aux erreurs.
Le système Apply transforme un seul bloc de texte (la "Snippet") en une architecture de fichiers complexe.
C'est ce qui permet à l'IA d'agir comme un développeur à distance : elle te donne le plan, tu le colles, le système construit.
2. Le Format Sacré
Pour que apply.js comprenne qu'il doit créer un fichier, il cherche un marqueur très précis.
Le Marqueur
code
Text
[[[ FILE: chemin/vers/le/fichier.extension ]]]
Règles de Syntaxe
Trois crochets ouvrants [[[ et fermants ]]].
Le mot clé FILE: (en majuscules de préférence pour la lisibilité).
Le Chemin relatif complet (ex: server/routes/api.js).
La Regex actuelle (v5) est robuste : elle accepte les espaces dans les noms de fichiers (ex: [[[ FILE: assets/mon image.png ]]]).
3. La "Snippet" (Le Pavé de Code)
Une "Snippet" est un bloc de texte unique que je t'envoie. Elle contient souvent plusieurs fichiers à la suite.
Exemple de Snippet valide :
code
Text
[[[ FILE: dossier/fichier1.js ]]]
console.log("Je suis le fichier 1");

[[[ FILE: dossier/styles/style.css ]]]
body { background: black; }

[[[ FILE: racine.txt ]]]
Je suis à la racine.
Pourquoi tout mettre dans un seul bloc ?
Cohérence : Si je modifie une fonction dans le serveur et son appel dans le client, les deux changements sont appliqués en même temps. Le projet ne reste pas dans un état "cassé" entre deux copier-coller.
Vitesse : Tu fais 1 Copier -> 1 Coller dans update.txt -> 1 Sauvegarde. C'est tout. Le script gère la création des dossiers, l'écrasement des fichiers et le nettoyage.
4. Fonctionnement Technique (apply.js)
Surveillance : Le script tourne en boucle (toutes les secondes) et regarde le fichier update.txt.
Détection : Dès qu'il voit du contenu, il le lit.
Découpage (Split) : Il utilise une expression régulière (Regex) pour couper le texte à chaque marqueur [[[ FILE: ... ]]].
Écriture :
Il regarde le chemin demandé.
Si le dossier n'existe pas, il le crée (mkdir -p).
Il écrit le contenu dans le fichier (writeFileSync).
Nettoyage : Une fois fini, il vide update.txt pour qu'il soit prêt pour la prochaine snippet.
⚠️ À SAVOIR
Écrasement : Ce système écrase le contenu précédent du fichier ciblé. Il ne "rajoute" pas de lignes à la fin. C'est pourquoi je renvoie toujours le fichier complet.
Blocage : Si apply.js semble ne rien faire, c'est souvent parce que update.txt n'a pas été sauvegardé (Ctrl+S) ou qu'il y a une erreur de syntaxe dans le marqueur (d'où l'importance de copier mes snippets exactement).
